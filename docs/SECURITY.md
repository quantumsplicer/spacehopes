# Security

The owner is a public official, so every input is treated as hostile.

## Sign-in (Studio)

Login ID + password. The starting credentials are `admin` / `admin@123` and **must be changed**: the Studio shows a banner, and with `ENV=prod` every API call except "change password" is refused (`password_change_required`) until it is.

What stops someone who can only see the login page:

* **Guessing is throttled on the server**, per connection *and* per login ID (so rotating IPs or targeting one account both slow down): the first 3 failures from a connection are free, then waits of 15 s, 30 s, 60 s ... up to 15 minutes (HTTP 429 with `Retry-After`; the right password also waits). Per-ID waits start after 6 failures. Success clears the counts. A per-minute rate limit sits on top, and Cloudflare Turnstile guards the form in production.
* **The front end throttles too** (5 s after the third wrong attempt, doubling to 5 minutes, remembered across refreshes, plus an 800 ms double-submit guard). That is only a speed bump and a courtesy; the server never trusts it.
* **No hints**: wrong password and unknown ID give the identical message and the same throttling; unknown IDs still run a full password hash, so timing does not reveal which IDs exist. Failures are audited without storing anything that was typed.
* **Passwords** are hashed with **scrypt** (N=2^15, r=8, p=1, 16-byte random salt per password) and compared in constant time. Policy for a new password: 12 to 128 characters, at least three kinds of characters, not a common password (`admin@123`, `password...`), not containing the login ID, different from the old one.
* **Changing the password** needs the current password (own throttle), then **revokes every session** (including the current one) and issues a fresh one, and emails the owner. The login ID can be changed in the same step.
* Sessions: random token in an `httpOnly`, `Secure` (outside dev), `SameSite=Strict` cookie; only its SHA-256 is stored. A new session on every sign-in. **12-hour absolute** and **30-minute idle** timeouts. CSRF header on every write plus an `Origin` check (login and logout included).
* Roles: **owner**; optional **editor** (drafts and moderation only; cannot publish, change settings, export subscribers, add users or read the audit log). The owner creates an editor with a first password; the editor must change it at first sign-in.
* Every sign-in and every change is written to `audit_log`, which is **append-only** (a Postgres trigger rejects `UPDATE`, `DELETE` and `TRUNCATE`). Each sign-in also emails the owner.

**Known trade-off:** because wrong guesses on a login ID slow that ID down for everyone, a determined attacker can keep the owner waiting (never more than 15 minutes at a time) but cannot get in. Cloudflare rate-limit rules in front of `/api/v1/studio/auth/*` (see `docs/DEPLOY.md`) reduce that.

### Resetting a password (forgotten, or locked out for good)

On the server: `docker compose exec api python -m app.cli reset-password <login_id>` prints a new random password and forces a change at the next sign-in.

## Public input

* Pydantic validation on every body, with length caps (name 60, comment 2,000, contact message 4,000). Comments are **plain text**: sanitised on input, rendered escaped, links never clickable.
* Comment checks: rate limit 5 per 10 minutes per salted fingerprint, more than one link flags it, English/Hindi blocklist (editable), duplicate detection, hidden honeypot field, Turnstile. Flagged comments always wait for a human. Hidden comments are kept, never hard-deleted.
* **No raw IPs or user agents are stored.** Blocks and rate limits use `sha256(salt | IP | user agent)`. Analytics store only daily totals.
* Subscribe and sign-in codes give the same answer whether or not the address exists.

## Uploads

Magic-byte sniffing (JPEG, PNG, WebP, HEIC only; **SVG and everything else rejected**), 25 MB streamed cap, decompression-bomb guard (64 MP), every image **re-encoded** (this strips all EXIF and GPS), random storage keys, private bucket served through the API proxy with `nosniff`. Drawing SVGs are generated by the server from validated JSON, and served with a sandboxing CSP.

## Browser and network

* Strict **CSP with per-request nonces** (`script-src 'self' 'nonce-…' 'strict-dynamic'`, Cloudflare Turnstile and YouTube-nocookie frames only), `frame-ancestors 'none'`, HSTS, Referrer-Policy, Permissions-Policy, `X-Content-Type-Options`, COOP/CORP.
* OpenAPI docs exist only when `ENV=dev`.
* Secrets come only from the environment; nothing sensitive is logged (emails are redacted from mail errors; audit entries hold ids and actions).

## Database and dependencies

SQLAlchemy ORM / bound parameters only. Python dependencies are pinned in `api/requirements.txt`; `pip-audit` and `npm audit` run in CI (`.github/workflows/ci.yml`) and with `make audit`.

## Retention and backups

* `audit_log` is kept indefinitely. For CERT-In's **180-day** log retention, ship container logs (`docker compose logs`, or the Docker `json-file`/journald driver) to storage that keeps them 180 days; Caddy access logs are the other half. Nothing in the logs contains IPs of commenters beyond Caddy's own access log.
* **Nightly encrypted backup** at 03:00 IST: `pg_dump` encrypted with a key derived (scrypt) from `BACKUP_PASSPHRASE`, plus a media manifest, uploaded to the bucket under `backups/`; the newest 14 are kept. **Use a separate R2 bucket or account for backups in production.** `make restore` was tested by restoring into an empty database (row counts matched).

## Known limits

* `npm audit` reports one **moderate** advisory in TipTap v2 (`mergeAttributes()` and a `__proto__` key; GHSA-cp6q-959q-f8rh). TipTap is used only inside the signed-in Studio editor; public pages never run it, and the API rebuilds every post body from a strict whitelist of node types and attributes before saving. The fix is the breaking TipTap 3 upgrade, which should be done and re-tested (editor, slash menu, node views) rather than forced. CI fails only on high severity.

* Copy protection is a deterrent only (screenshots cannot be blocked).
* Rate limits of the public POST endpoints use the connecting address Caddy forwards; keep the API unreachable except through Caddy.
